# Site permission decisions (Vek 0.3)

This independent host implementation closes a browser-management gap; it does not establish that every inherited Ego Chromium permission surface has equivalent behavior. Evidence for Ego's browser permission/setting resources remains bounded in `client-resource-feature-ledger.md`.

`app/site-permissions.cjs` uses profile + top-level HTTP(S) origin + requesting-frame HTTP(S) origin + capability. Microphone and camera are separate, including combined media requests; an unknown media type cannot inherit a broader grant. Saved rules support allow/block/ask; ask removes the stored decision. The root Settings screen edits the active website and saved embedded-site rules. Older origin-only non-media grants migrate to the same top/requesting origin; older broad media grants are intentionally not widened to both devices.

The real Electron session installs both permission check and request handlers, as required by [Electron's Session API](https://www.electronjs.org/docs/latest/api/session#sessetpermissioncheckhandlerhandler). The installed Electron 42 type declarations were also read to pin actual fields (`requestingUrl`, `securityOrigin`, `mediaType`, `mediaTypes`). Chromium secure-context rules and OS permissions still apply; a rule is not an OS permission override.

Native requests offer block once, always block, allow once and always allow. A prompt hands an Agent Space back to the user; the user must explicitly return control. Allow once lasts only for that tab document. Any non-same-document frame navigation, tab destruction or app shutdown revokes it and resolves pending callbacks as false. Duplicate same-document requests share a single prompt. Responses after navigation/destruction/timeout cannot persist a grant. Any explicit matching allow/block/ask/reset invalidates older pending prompts. Pending-entry identity prevents an expired dialog from consuming a newer same-key request. A per-request AbortSignal also dismisses a stale native dialog. Pending prompts are capped at 16 and time out after 60 seconds.

Opaque/file/custom origins, absent/destroyed WebContents, unsupported devices/filesystem/display capture, and unknown capabilities are denied. This module does not implement USB/HID/serial device choosers, desktop capture, service-worker permission prompts, automatic stream shutdown or storage-access exceptions. Resetting a rule changes future checks and requests; reload or close pages to terminate already-open device streams. Permission revocation does not claim to cancel an existing OS device stream.

API: `permissions:snapshot`, `permissions:set {origin,requestingOrigin?,permission,decision:'ask'|'allow'|'block'}`, `permissions:remove {origin}`. The host derives profileId from the selected Space and does not accept a supplied profile override. The CLI exposes these actions through the token-protected local API; website renderers do not receive the chrome API.

Tests use synthetic origins and documents for stale prompt races, profile/frame/device isolation, callback deduplication, timeout, expired-key reuse, ask/reset revocation, explicit opaque origin precedence, conservative migration and invalid rules. Real-host workbench coverage queries Chromium notification permission state and issues a pre-blocked notification request on a loopback fixture. It does not show notifications, access device streams, read the clipboard or contact a location service. See `reports/site-permissions-test.log` and the latest workbench integration log for completed results.
