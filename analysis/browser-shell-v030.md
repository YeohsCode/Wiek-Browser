# Browser shell changes in Vek 0.3

`app/main.cjs` and `app/renderer.js` now scope bookmark/history/download listings and modifications to the selected browser profile. Legacy rows with no profileId belong to Default. Chromium and Vek archive imports attach the destination profile; profile exports filter bookmarks as well as history. Deduplication includes the profile, so a URL in another profile no longer suppresses its import. Clearing history or removing a bookmark leaves other profiles intact. No private source browser was read during these tests.

Website permissions have their own capability and frame rules; see `site-permissions.md`.

Download management now exposes the real Electron DownloadItem pause, paused status, canResume and resume while the native item remains available. Inactive/cancelled/completed items do not show a misleading Cancel button. Reloaded metadata cannot claim to resume a previous process's DownloadItem; interrupted cross-restart recovery remains unavailable. Servers without range/validator support may restart a resumed transfer, as documented by Electron. CDP Page.setDownloadBehavior may leave Electron's savePath empty even when the file was saved; SDK-owned destinations remain managed by the SDK. The manager does not infer an unknown save location.

The workbench integration fixture now serves a real 2 MiB throttled loopback download with Range/ETag/Last-Modified. It verifies pause state, stable received bytes during pause, resume, and exact resulting bytes on disk. It uses the SDK's page-scoped Page.setDownloadBehavior rather than a native save dialog. An initial fixture used Browser.setDownloadBehavior without a matching browser context, leaving a native destination dialog; this failed attempt is retained in v030-workbench-source-r3.log. The next attempt incorrectly expected the CDP-overridden destination in Electron getSavePath, and is retained in r4.log. The final r5 fixture verifies the real configured path; no product assertion or upstream case was weakened.

Native webpage context menus now provide link new-tab/new-Space/copy/save, image copy/save, editable spelling/edit actions, selection copy/Library/agent draft/web search, navigation and inspect. Opening a context menu explicitly hands an Agent Space to the user. Link navigation permits HTTP(S); selected text passed to Ask only becomes a draft. These are independent browser features; the bounded PAK evidence does not prove every Ego context-menu arrangement.

Source-host integration completed 43 checks in `reports/v030-workbench-source-r5.log`. The final packaged host completed 48 checks in `reports/v030-package-workbench.log`, additionally covering scoped RPC profiles and actual checkpoint restore/protection. This is independent of the upstream 69-case SDK suite and cannot replace its package regression. The first source integration failed because the new permission probe claimed a personal Space as an Agent task, then the older bulk-close test correctly preserved that running Space; the fixture now explicitly finishes the claimed task before the existing personal-Space assertions. That failure is retained in v030-workbench-source.log.
