# Wiek Browser：原产品依赖与名称残留审计

日期：2026-11-09，Asia/Shanghai。审计基线提交：`55f5d5934fbbcc2351d6c4332fe8af81acf5483b`；本机安装包版本：0.22.0。工作区另有未提交的本地服务标题功能，不属于该安装包。本次只检查和生成报告，没有替换命令、修改全局Skill、停止浏览器或改动产品实现。

## 结论

**你的观察成立：迁移没有完成到系统入口、SDK输出和全部随包文档。** 当前存在四种性质不同的情况：

1. **实际原浏览器入口仍在使用环境中。** 全局`ego-browser`命令仍指向原安装；全局浏览器Skill仍要求优先调用该命令；`wiek-browser`没有安装到当前PATH。进程快照同时发现原浏览器和Wiek在运行。
2. **Wiek运行时确实复用上游开源SDK。** 适配层仍使用`globalThis.ego`、`EGO_*`错误码和环境变量。这里的`ego`对象由Wiek自己实现，通过本机RPC连接Wiek宿主，不是直接调用原浏览器的对象。
3. **随包安装脚本、部分用户指导和提示文案没有替换完整。** 这些会误导用户或Agent返回原产品，属于交付遗漏；不能都用兼容性解释。
4. **原始测试、对照工具、研究记录和第三方署名有保留理由。** 应与正式产品入口隔离，而不是把所有字符串统一替换，也不能把所有命中都叫作运行依赖。

Wiek的Electron宿主与界面已经采用自身实现。当前发行内容检查未发现原浏览器下载目录、原生应用包或私有服务目录被装进Wiek。这个结论不表示SDK已经独立重写，也不表示系统默认Agent入口已经迁移。

## 逐项原因与处理意见

### 1. 系统默认命令和全局Skill没有迁移——交付遗漏，优先处理

本机只读检查发现：

- `~/.local/bin/ego-browser`在PATH上，最终解析到本项目下载目录中0.6.2.7版原浏览器的原生CLI。
- `~/.local/bin/wiek-browser`不存在；当前PATH也找不到该命令。项目内和安装包内的Wiek CLI文件确实存在，但没有完成全局注册。
- `~/.agents/skills/ego-browser/SKILL.md`存在，内容要求默认优先使用原命令；`~/.agents/skills/wiek-browser/SKILL.md`不存在。
- 项目内`.agents`/`.codex`有Wiek入口，同时仍保留原名入口；`.claude/skills`仅发现原名入口。入口并存不等于默认路由已迁移。
- 快照发现**8个原浏览器相关进程、6个Wiek相关进程**，包含辅助进程，不是8个和6个独立浏览器实例。完整PID和可执行路径见机器清单。没有读取进程参数或浏览页面。

**为什么没替换：** 之前完成了项目内品牌与运行宿主切换，保留原安装用于对照测试，但没有把“安装并注册Wiek全局命令/Skill、核对Agent默认选路”做成发行验收项。这是范围遗漏。仅凭本次进程快照无法认定每个原进程由哪一次操作启动，不能把原进程都说成Wiek启动的子进程。

**应当处理：** 给Wiek安装独立命令和全局Skill，明确默认Agent入口指向Wiek；原安装保留为显式选择的对照工具。无需把原命令偷偷改成另一个产品。

### 2. SDK和宿主协议仍使用原标识——有兼容理由，需要隔离

证据：

- [CLI装配](../cli/wiek-browser.mjs#L71)设置`EGO_BROWSER_STATE_DIR`、`EGO_BROWSER_AGENT_WORKSPACE`，创建适配对象并赋给`globalThis.ego`。
- [CLI适配器](../cli/wiek-browser.mjs#L196)通过Wiek自己的本机RPC调用`createTab`、`snapshot`、`sendCDPMessage`等方法。
- [SDK运行时](../packages/sdk/src/browser-runtime.ts#L350)读取`globalThis.ego`；[SDK装配](../packages/sdk/src/index.ts#L45)保留`disposeEgoSdk`、`installEgoSdk`及包装标记。
- [错误码](../packages/sdk/src/ego-errors.ts#L21)、[宿主错误](../app/main.cjs#L86)、[快照错误](../app/snapshot.cjs#L220)保留`EGO_*`契约。
- SDK临时文件、剪贴板锁、CDP object group、定位器world、输出标记和缓存默认路径也保留原前缀。它们是SDK内部命名，不等于访问原浏览器服务。

**为什么没替换：** 当前方案复用了MIT许可SDK，并要求原始测试断言和fixture语义保持不变。直接替换这些标识可能破坏既有脚本和错误判断。保留兼容层是有意选择；但它不要求用户看到原产品升级提示，也不要求把原安装脚本放进发行包。

**应当处理：** Wiek成为产品主命名空间，原对象/错误契约收敛到明确的兼容适配层；逐步增加Wiek命名接口和迁移验证，继续保留原测试输入。CLI目前将SDK状态目录指定到Wiek数据目录；SDK单独执行时仍存在`.ego-browser`等默认回退，需单独验证隔离。

### 3. 安装包仍含原安装脚本和原名Skill——不应继续保留为产品入口

安装包中确认存在两份原名Skill相关资源：顶层`skills/ego-browser/`，以及SDK构建时复制到`packages/sdk/dist/out/agent-skills/ego-browser/`的副本。

- [安装脚本](../skills/ego-browser/scripts/install.sh#L7)保留原CDN下载地址，应用名称为原产品。**执行这个脚本会安装原产品。** 本次没有执行它；没有证据显示普通Wiek启动会自动运行它。
- [安装指导](../skills/ego-browser/references/install.md#L1)仍指向原产品官网、安装和升级命令。
- [兼容Skill配置](../skills/ego-browser/agents/openai.yaml#L2)虽然图标已改为Wiek，但默认提示仍调用`$ego-browser`。
- [SDK构建器](../packages/sdk/scripts/build.mjs#L26)从上述原名Skill目录复制资源；[打包配置](../package.json#L43)同时收录原名Skill和整个SDK构建目录。

**为什么没替换：** 构建链保留了原Skill作为SDK构建输入，发行配置又把整个构建结果收录了进来。此前只处理了图标和部分入口，没有为产品包生成完整的Wiek版Skill，也没有禁止原安装器进入发行包。这是构建/打包遗漏。

**应当处理：** 原始Skill可留在开发/测试输入中；正式包只发布适配Wiek的指南、站点学习资料与配置，排除原安装/升级脚本。增加安装包内容检查，防止后续SDK构建重新带回。

### 4. 用户可见指南和SDK提示仍有原品牌——清理不完整

- `wiek-browser skill`目前读取原SDK指南，只执行小写`ego-browser → wiek-browser`替换，见[CLI第39行](../cli/wiek-browser.mjs#L39)。
- 本次实际执行只读的`skill`命令后，输出仍含`Ego-browser`、`Ego Lite profile`、原产品更新提示等内容。
- 原指南里的升级命令被机械替换为`wiek-browser upgrade`，但当前Wiek CLI没有该子命令。这不只是文字问题，还会给出不可执行的指导。
- [SDK更新提示](../packages/sdk/src/update-notice.ts#L31)、迁移提示、剪贴板诊断、输出前缀等仍保留原名。更新提示只在宿主返回`updateAvailable:true`时触发；[当前Wiek宿主](../app/main.cjs#L337)固定返回false，因此不能把这段静态代码说成正在自动升级或请求原服务。
- [Wiek安装说明](../skills/wiek-browser/references/install.md#L5)仍有一句原产品名称，虽是在阻止错误下载，但仍不符合既定文案要求。
- [关于页](../app/renderer.js#L159)显示SDK来源项目；这是署名说明，适合收敛到第三方许可入口，不能与SDK功能依赖混算。

**为什么没替换：** 先前只扫描10份指定的主要文档；没有覆盖实际渲染的`skill`输出、SDK源码/生成物、嵌套引用和全局安装目录。小写字符串替换也覆盖不了大小写、语义和命令能力差异。我此前对“文案已清理”的表述范围过宽，应当明确限定为那10份文件。

**应当处理：** 用Wiek专用指南替代机械替换，核对每条命令真实可用；对实际CLI输出和最终安装包运行检查。原始测试断言保留，不把用户指导留给兼容层决定。

### 5. 对照测试、评估框架和历史证据——按来源保留，继续隔离

- 原浏览器的下载制品和`tools/ego-reference-cli`用于显式对照测试。
- SDK原始测试仍验证原接口契约；评估框架保留上游模块和路径。当前独立CI中的相关名称来自固定上游框架，不是拿原浏览器替代Wiek宿主。
- 157份报告/历史文件、40份研究文档的命中主要用于保存原始来源、版本、输入和结果。历史日志不应为了消除字符串而改写。
- 本地可见的旧`ci.yml`、缓存清理、星标图工作流经核实**均被Git忽略、未跟踪**；当前仓库唯一跟踪的工作流是`wiek-ci.yml`。不能把这些本地文件误报为仍向原仓库运行的GitHub自动化。

**为什么没替换：** 对照身份和原始输入需要可追溯，名称改写会破坏记录的真实性。应保留在开发/研究范围，与产品发行包分离。SDK构建中夹带的安装器不属于这个豁免范围。

### 6. 许可署名和图标——分别判断

上游代码的[LICENSE](../packages/sdk/LICENSE)和[NOTICE](../NOTICE.md)应保留已有版权、许可及来源信息；这不能作为产品入口继续使用原命令的理由。

本次另核对安装包中10份SVG/PNG/ICNS资产，已知两份原PNG哈希未命中，包图标与自有ICNS匹配。旧Skill名称下的图标也已换成Wiek图标。这个检查只证明已知资产身份，不是所有视觉资源的穷举相似性证明。

## 为什么此前没有发现完整范围

- 把外层产品品牌迁移、SDK兼容、系统安装迁移当成了一个完成项，实际只完成其中部分。
- 以10份主要文档的扫描代替了发行包和实际CLI输出的检查。
- SDK构建复制了原Skill，打包规则又收录生成目录；缺少禁止原安装器进入产品的检查。
- 原安装用于对照保留是合理的，但系统默认Skill/命令没有与日常Wiek入口分开。

因此，**兼容代码的保留有技术依据；用户指导、安装器和默认入口的遗漏需要修正。** 我不应把它们一起称为“只是历史名称”，也不应把品牌迁移描述成系统迁移已经完成。

## 建议处理顺序

1. **P0：系统入口。** 安装Wiek独立CLI和全局Skill，核验Agent实际选路；原浏览器仅用于显式对照。
2. **P0：随包误导。** 移除原产品安装器/升级指导，提供完整Wiek指南，检查实际输出和最终包内容。
3. **P1：内部命名。** 将SDK品牌/提示/状态配置与协议兼容层分开；保留原测试，增加迁移与隔离验证。
4. **保留并隔离。** 许可署名、原始测试、对照工具和历史记录按来源保留。

本次没有实施以上迁移，避免把“统计报告”与未验证的修复混在一起。既有标题功能改动保持原状。另记录一个验证边界：0.22.0独立CI实际为失败，原因是资源/记忆面板测试等待超时，后续打包步骤未运行；不能把先前本地通过结果扩展成这一轮远端CI通过，见[原始CI状态](p4-ci-42132702954-status.json)。
