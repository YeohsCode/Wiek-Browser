# Vek 0.2.0 shell integration

The native main process integrates the independently implemented workspace/Git, MCP, local Agent, voice, catalog, Library, recorder and preference services. Remote page WebContents receive only the narrow prompt bridge and isolated preload handlers; trusted chrome IPC checks the actual sender. The token-protected loopback API adds `workbenchAction` for the local CLI and integration tests.

Preferences apply to the actual native menu, Chromium color preference and WebContentsView bounds. Horizontal content starts at (230,116); vertical layout starts at (410,64). Shortcut conflict validation includes edit/print/find/developer-tool chords reserved by the host. User-selected instructions enter provider context; optional browsing context is filtered to the thread's Space and omits URL queries/fragments. Local-file context lists only bounded top-level project names. These are bounded context features, not a global memory index.

Detached Space windows reparent the same WebContentsViews, preserving tabs and renderer state. Their chrome IPC is restricted to that Space's navigation/tab/ownership/find operations. Closing the detached window returns its views to the main window. Main-window closure leaves the app alive when background mode is enabled or detached windows exist; the native tray can restore the window or quit the app. Recently closed user Spaces retain up to 30 restorable tab lists and restore as personal Spaces without restarting providers.

Library capture and action recording use the real renderer image. Testing exposed Chromium `UnknownVizError` when capturing a hidden resized view. The host now briefly renders that requested page at its actual viewport, invalidates its compositor, captures pixels with bounded retries for surface errors, and restores the normal panel layout in `finally`. It does not synthesize screenshots or turn a failed capture into a pass. Recorder post-capture checks discard images if recording stops or the active page changes.

Browser state saves use private atomic replacements and synchronous shutdown flushing after startup restore has completed. A failed restore preserves the existing file. Download metadata, unpacked extension locations/enabled state, home shortcuts, pinned Spaces and recent closure records persist. A restored unfinished download is marked interrupted; it is not described as resumed.

Real host integration tests exercise workspace conflict refusal, a genuine fake-provider → packaged CLI → SDK → browser action chain, MCP pairing and target isolation, manual handoff/revocation, real layout/theme effects, image/page Library saves, native detached/reattached windows, pinned/bulk/restore behavior, bundled Whisper inference, and trusted versus untrusted recorder input. No paid model turn, personal browser import or external account action is performed by these tests.
